# Frontend at synthesis, measured standalone

The session scripts behind `ideas/xiangshan-frontend-synth.md`: Frontend's
synthesis netlist and the generated register files, timed in a plain
OpenROAD session so a netlist rebuilt by `tools/fanout_tree`, or a
register file regenerated by `tools/structured_gen`, is measured without
a flow run. Nothing here is a bazel target.

Inputs, once per Frontend synthesis:

- `XS_LIBS`: the liberty set `Frontend_synth_odb_debug` reads (its run
  log's `read_liberty` lines), the platform's `.lib.gz` decompressed.
- `XS_SDC`: that session's `1_synth.sdc`; `XS_SETRC`: the platform's
  `setRC.tcl`.
- `XS_FTQ_LIBS`: a directory with the four `Ftq*.lib`, the generator's
  formula ones from the memories directory or characterised ones.

Frontend's netlist, one line per measurement:

```
XS_ODB=<dir>/1_synth.odb XS_TAG=s10 XS_OUT=results.txt \
  openroad -exit -no_splash time_frontend.tcl
XS_ODB=<dir>/1_synth.odb XS_OUT=classes.txt openroad -exit -no_splash classify.tcl
```

`time_frontend.tcl` gives the `reg2reg` minimum period, the endpoints
over 1,000 and 950 ps and the worst path; `classify.tcl` which of those
endpoints pass a macro, their histogram, the worst period not through
`FtqMetaQueueResolve` and the worst path through no macro. The file name
must be `1_synth.odb` only for odb-debug, which reads the stage from it.

The netlist of S10, from the flow's `1_synth.odb`:

```
fanout_tree --odb 1_synth.odb --out s10/1_synth.odb --liberty <each XS_LIBS file> \
  --buffers BUFx2_ASAP7_75t_R,...,BUFx24_ASAP7_75t_R --max-fanout 32 --max-load-ff 48 \
  --upsize-all --weak-ff-per-drive 5 --dont-use xp,x1p
```

A register file, generated with the spec's buffer and pin keys, then
timed and characterised on its own gates:

```
structured_gen --spec <spec> --lef <tech lef> --lef <cell lef> --odb rf.odb
RF_ODB=rf.odb RF_OUT=read.txt openroad -exit -no_splash time_array.tcl
RF_ODB=rf.odb RF_CELL=FtqMetaQueueResolve RF_LIB=FtqMetaQueueResolve.lib \
  openroad -exit -no_splash characterise_array.tcl
```

The spec lines for the characterised Ftq queues of S7 onwards:

```
buffer_cells BUFx2_ASAP7_75t_R BUFx3_ASAP7_75t_R BUFx4_ASAP7_75t_R BUFx4f_ASAP7_75t_R BUFx6f_ASAP7_75t_R BUFx8_ASAP7_75t_R BUFx10_ASAP7_75t_R BUFx12f_ASAP7_75t_R BUFx16f_ASAP7_75t_R BUFx24_ASAP7_75t_R
buffer_fanout 16
buffer_max_wire_um 80
pins_at_columns 1
```

and `bit_folds 4` in place of 8 on `FtqMetaQueueResolve`.
